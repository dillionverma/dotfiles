# Apple App Store

App Store campaign links use static tokens, not ad-platform macros. Apple Ads
campaign, ad group, and ad IDs arrive through AdServices attribution, separately
from these URL parameters.

## Parameters

| Parameter / macro | Meaning | Example value | Notes |
|---|---|---|---|
| `pt` | Developer account provider token. | `123456` | Generated by App Store Connect. Shared across that developer's campaign links. |
| `ct` | Campaign token. | `summer_launch` | Appears as the campaign name in App Analytics. Use with `pt`. |
| `mt` | Media type token. | `8` | Apple's generated app campaign links use `8`. |
| `ppid` | Custom product page ID. | `eb2b3606-2fef-4aab-a54e-b2e5547c9bc3` | UUID in the custom product page's generated URL. |
| `app` | App Store product variant. | `messages` | `app=messages` opens the iMessage product page. |
| `action` | App Store action. | `write-review` | Opens the review sheet. Not attribution. |

## Automatically added parameters

App Store campaign links have no documented equivalent of `ttclid`, `fbclid`,
or `gclid`. App Store Connect generates the campaign and product page URLs.

## Notes

- The app ID is in the path, such as `/id123456789`, not a query parameter.
- App Store Connect campaign tokens allow up to 30 characters, with the
  character rules in the campaign links source. StoreKit documents a separate
  40-byte limit. These are different interfaces.
- A region path such as `/us/` does not restrict the link to that region.
- Combining `ppid` with `pt` and `ct` is not explicitly documented by Apple.
- Apple Ads attribution payloads and SKAdNetwork postbacks are separate from
  App Store URL parameters.
